# Security Policy

## Reporting a vulnerability

Please do **not** publish exploitable security details in a normal issue.

Use GitHub private vulnerability reporting when it is available for this repository. If that option is unavailable, contact the maintainer privately through their GitHub profile and provide only the minimum information needed to establish a private reporting channel.

Include:

- affected revision/version
- reproduction steps
- realistic impact
- suggested mitigation if known

## Scope

Security reports should concern the project's own code, build tooling, dependency usage or release infrastructure. Copyright/ROM policy questions belong under `docs/PUBLIC_SOURCE_POLICY.md`, not the security process.
