# Screenshot and Public Media Policy

Screenshots are part of the project's public technical record. They must show the real application and must be safe to redistribute.

## Acceptance requirements

A screenshot may be committed when it:

- comes from the current/referenced development build;
- does not expose local filesystem paths, usernames, environment variables, tokens or private repository data;
- does not show internal memory/agent notes or private-only debug material;
- is labelled honestly when it shows a debug/development view;
- does not imply that an incomplete fidelity area is already ROM-exact;
- has a clear purpose in README, documentation, an issue or a release.

## Preferred public set

The first repository-native gallery should cover:

1. Main Menu
2. Story
3. Versus / Battle Setup
4. Battle
5. Characters
6. Deck
7. Cards
8. Settings

Use stable filenames under `docs/media/screenshots/` and replace a screenshot only when the new capture represents a newer public baseline.

## Fidelity captures

For timing/camera research, a single screenshot is not enough. Pair screenshots/contact sheets with tick/state evidence such as shot, viewport motion, actor/target state and projectile lifecycle.
